# Review demo walkthrough — not a recording

Use a dedicated test account and synthetic workshop content. Keep passwords,
tokens, unrelated chats and customer files off screen. Screenshots and this script
are not substitutes for an actual recorded demonstration.

## Rehearse first

1. Open the canonical GraphicRouter development plugin in a fresh ChatGPT chat.
   Show the plugin name/version and start positive case1 from the case file.
2. Complete a short adaptive brief using the synthetic Workshop day example.
   Choose native blank-canvas composition. Show the actual briefing handoff.
3. Run positive case2. Show the actual saved preview, separate native elements,
   version and PowerPoint download. Do not describe prepared replay as live output.
4. Run positive case3. Show the teal headline, unchanged other objects and new
   immutable version/change summary. Keep the initial version visible for comparison.
5. Use the dedicated Canva account for positive case5. Show actual import status,
   editor link and independent text/shape editing. A screenshot of the PPTX is
   insufficient. If the import fails, fix the flow before recording success.
6. Ask the unsupported narrated-MP4 request from negative case1. Show the clear
   limitation without a fabricated video or unrelated GraphicRouter calls.

The full twenty-page case is a separate review run; include a short actual
storyboard/requirement/export segment if claiming that workflow in the recording.
Do not show a partially composed deck as a complete twenty-slide presentation.

## Record and host

Computer/browser control is available, but no video-capture capability has yet
been verified. Check available recording support first. If none exists, the
publisher starts/stops their screen recorder while the walkthrough is performed.
Use the rehearsed actual interactions. Playback must show readable prompts/results,
cover the claimed workflows and contain no exposed secrets.

Host the real video at a reviewer-accessible destination chosen by the publisher,
verify playback without private login, then record its actual URL in submission
metadata. Until that URL is verified, demo status remains **Incomplete**.

Reviewer account credentials belong only in secure submission-portal fields,
not the ZIP, repo, video, listing or this walkthrough.
