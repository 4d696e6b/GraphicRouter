Slide 3
The blueprint records the elements, their content, positions, order, and styles. We use that same data for the layout preview, content preview, finished preview, and PowerPoint. That gives us a concrete source of truth to inspect and revise. The renderer checks text fit and slide bounds. If copy does not fit, it returns a clear error instead of silently shrinking or discarding it.

Expanded notes
Here is the construction process. The input contains the brief, five slide messages, a composition choice for each, and speaker notes. The engine converts that into a blueprint containing named elements with positions, sizes, order, and styles. We can show the layout boxes, then the content, then the finished slide. All of those views consume the same blueprint that the PowerPoint compiler uses. This avoids maintaining an independent preview layout that can drift from the export. The engine also checks text fit, unsupported characters, invalid bounds, missing source elements, and overlapping content boxes. An invalid change returns an actionable error while the previous version remains intact. That explicit representation is what makes precise revisions possible.
