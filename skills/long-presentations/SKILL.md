# Long presentations and chapters

Use after presentation-storytelling when the requested deck needs multiple sections or more than five pages. Confirm supplied page/time constraints; do not equate more slides with a better story. Native documents support at most 40 pages, 200 elements per page and 4000 total. Propose a split if the content exceeds these bounds, without silently dropping material.
Create an ordered chapter map. Each section answers a distinct audience question and ends with a supported conclusion or transition. Allocate time to the decisions and difficult explanations, not equally across slides. Separate the core speaking route from appendix material. Keep explicit stable IDs and section names so a later page reorder does not change references.
Use a consistent system for section dividers, navigation, page numbering and recurring labels, while varying compositions according to content. Review a storyboard/contact sheet: repeated messages, long runs of dense pages, abrupt transitions, unexplained terms, inconsistent vocabulary and evidence gaps. A claim cannot become stronger merely through repetition.
create_document starts all storyboard page shells. edit_document can add/remove/reorder pages, update page messages/sections/notes and edit page objects. Reorder requires each current page ID exactly once. Keep related but independent notes; changing one headline must not rewrite the deck. Remove unused blank pages before export. Inspect source pages individually and inspect all imported Canva pages before claiming full editability. For very long projects build and review chapters incrementally; do not repeatedly return all large previews to the model.
For long and detailed user input, preserve the original before composing. Use append_document_requirements to save ordered verbatim source chunks (12000 characters/chunk,120000 total) and extract a requirement ledger in batches of20. Include global brand/terminology rules, chapter/page-specific instructions, exact wording and sources, required slide count, forbidden content, visible-versus-notes placement, figures/units and unresolved contradictions. Give every requirement a stable ID and original chunk reference. Do not replace the original with a summary or infer missing facts. Reconcile conflicting instructions with one targeted question; retain both until resolved.
Create the whole storyboard, then fetch roughly3 pages at a time through get_document_context. It returns exact objects/notes and only relevant requirements; sourceChunkId retrieves one original chunk when needed. Reuse the shared theme and design intent across chapters. Mutations return compact checkpoints, not repeated full blueprints. Resume with the saved deckId/current version, incomplete pages and unresolved checks after an interruption. Native documents allow250 revisions,4000 objects and1800000 serialized UTF-8 bytes; if a real bound is reached propose a split without losing requirements.
After a chapter, inspect its actual pages and compare its content with every assigned requirement. Use review_document_requirements, including subsequent offsets, to find missing targets/copy, pending meaning review and conflicts. A mapped or text-present item is not automatically semantically satisfied. Save satisfied only after actual review and include a note; a relevant edit resets it. Mark extractionComplete only after comparing the complete original with the ledger. Export blocks incomplete extraction and unresolved registered must items, but cannot detect instructions never registered or independently certify semantic judgement. Preserve full original/ledger in companion notes, not the model's every response.
Long briefs must produce deliberate visual storytelling, not a wall of text repeated24 times. Assign a visual purpose to every slide: comparison, process, timeline, chart, image-led evidence or a focused statement. Vary adjacent compositions and chapter rhythm while sharing typography, spacing and colour roles. compose_slide supplies optional native hero/editorial/comparison/process/timeline/metrics/closing objects; compose_component supplies meaningful charts/icons. Use only supplied data and preserve mandatory detail in visible targets or notes as specified. Apply geometry to the intended blank page, inspect it and revise; do not overwrite composed pages automatically or pad them with unrelated decorative symbols.
