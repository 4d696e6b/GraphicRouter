# GraphicRouter — presenter cue sheet

This is the local-workflow pitch candidate. It is not a record of a completed live
rehearsal. Use speaker-notes.md for the actual core/expanded script.

## Before the stage

1. Open the five-slide PowerPoint or previously verified Canva deck. Open the
   matching saved GraphicRouter version in a second tab. Keep its deck ID and
   original version visible. Use create-deck.json for the exact supplied input.
2. Confirm slide 3 starts with a dark headline, not the already-violet v2. Rehearsing
   repeatedly against v2 does not demonstrate a visible colour change.
3. Put the original PPTX, violet PPTX, PDF, notes, and offline HTML on the presenting
   computer. Extract the ZIP first. Test the files offline on that computer.
4. For a live tool demonstration, confirm the actual account/tool connection and
   the presenter-owned Canva access. If unavailable, choose the local service demo
   or prepared replay and state the path accurately before demonstrating it.
5. Do not describe Canva shapes, lines, or font matching as verified until the
   presenter has independently checked them in the editor. Text/image draft editing
   was checked separately through the manual connector.

## Three-minute core timing target

- 00:00–00:33 / Slide 1: the problem. One small change should preserve existing work.
- 00:33–01:01 / Slide 2: plan, compose, direct. Distinguish local verification from
  the outstanding hosted account check.
- 01:01–01:36 / Slide 3: brief, blueprint, editable elements. Show the same plan
  behind construction previews and native export.
- 01:36–02:31 / Slide 4: about 25 seconds of proof narration plus a 30-second demo.
- 02:31–03:00 / Slide 5: working local flow and the concrete next milestone.

The core script contains 273 spoken words after removing bracketed directions.
This budget leaves 30 seconds for the demo: approximately 109 words/minute for the
spoken text. It is a planning target; rehearse aloud and measure actual transitions.
Expanded notes use the same five slides; select five-minute notes before export.

## Controlled edit on slide 4

1. Switch to the original presentation preview and select slide 3.
2. Ask: “Change only the headline on slide three to violet.” The structured change
   is set_element_color, elementId slide3.headline, color #7C3AED, against the current
   original baseVersion. Do not silently retry a stale-version conflict.
3. Show the new version, violet headline, and changed-element summary. The previous
   version remains available. The prepared proof compares all unrelated blueprint
   content and native slide/notes/media parts, allowing only that headline paint.
4. If the verified Canva deck is available, demonstrate its separate text/image and
   any editor-verified shape/line objects. This existing design is a different export
   version; do not imply the live revision has already synchronized to Canva.
5. Start a revised Canva import separately if configured. Its completion must not
   block the pitch. Manual Canva edits never synchronize back to the blueprint.

## Recovery language and actions

- Tool/account unavailable: “I’m switching to our local service demonstration.”
  Use this only when that service is actually running; the offline HTML is a replay.
- No working live service: “This is a precomputed engine replay of the same edit.”
  Open offline-rehearsal.html and use Replay verified headline edit. The GIF carries
  that same label. Neither is a screen recording or proof of a live account call.
- Slides unavailable: open graphicrouter-pitch-backup.pdf. It is a raster visual
  backup; use the PPTX to inspect editable native elements.
- Import pending or failed: keep presenting the saved deck. Use the existing Canva
  design or manual PPTX upload later. Do not start duplicate imports while polling.
- Recorded live demo: identify it as a recording. Capture one only after the actual
  intended workflow works; the scripted GIF cannot satisfy this requirement.
